# Occubuy Score SDK

This is the SDK for Occubuy Score, an embeddable widget that lets a partner
website (like a real estate site doing a tenancy application) ask a renter to
verify their Occubuy Score by connecting their bank, then decide themselves
whether to share that score with the partner.

The backend is real now (Express + Mongo, in `backend/`), running locally
against a sandbox Mongo - it's just not deployed anywhere public yet, and the
bank connection is still fake. This is a uni project (FIT3048, team102), not
a shipped product.

## What's in here

```
src/index.ts                 the actual SDK, this is what gets built and shipped
src/fastlink/                reference files copied from another repo, not part of the SDK build
backend/                     the real Express + Mongoose backend - see backend/README below
demo/mockPartnerWebApp.html  a fake partner site (JM Realestate) with the real SDK embedded in it
tests/                       vitest tests for the SDK
dist/                        built output, gets generated by `npm run build`
```

`backend/server.mjs` is gone - the SDK now talks to the real `backend/src`
Express server instead of a throwaway mock.

## Running it locally (for the demo / integration test)

You need three things running at once: the real backend, a static server for
the demo page, and a browser pointed at that page.

**1. Install dependencies (only needed once)**

```bash
npm install
cd backend && npm install && cd ..
```

**2. Build the SDK**

```bash
npm run build
```

This makes `dist/occubuy-sdk.iife.global.js`, which is the actual file the
demo page loads. If you skip this step the demo page will 404 on that script
and nothing will render.

**3. Start the backend (leave this terminal open)**

```bash
cd backend
cp .env.example .env   # fill in MONGODB_URI and OCCUBUY_HASH_PEPPER first
npm run dev
```

You should see `Occubuy backend listening on http://localhost:8787`. Leave
this running the whole time you're testing - it now serves the score API
*and* the fake FastLink bank page, both on port 8787.

**4. Seed the one demo partner (first time only)**

```bash
npm run seed:partner
```

Copy the key it prints and paste it into `demo/mockPartnerWebApp.html` as
`OCCUBUY_PARTNER_API_KEY`. There's no portal to issue this from yet, so this
script is the only way to get one right now.

**5. Start a static server for the demo page (open a second terminal)**

```bash
npx serve -l 5500 .
```

Run this from the repo root (`sdk-scaffold/`), not from inside `demo/`. The
demo page loads the SDK from `../dist/`, so it needs to be served from a spot
where that relative path actually resolves.

**6. Open the demo in your browser**

```
http://localhost:5500/demo/mockPartnerWebApp.html
```

## What to actually click through

1. Fill out the tenancy application form (name, email, phone, DOB, address -
   these are actually validated now, both here and again on the backend) and
   check the consent box.
2. Click **Start Verification**. The real SDK widget should render inline
   where the form was, not a popup.
3. Read the consent screen, check the box, click **Start Verification** again
   inside the widget.
4. On the bank connection screen, click either bank button. This is talking
   to the real backend's `/fastlink` route, not just a UI animation.
5. Watch it poll and land on a real score (a random number 0 to 999, plus a
   band based on that number).
6. Try **both** buttons here on separate runs: **Share with Partner** shows
   the result banner with the real score. **Don't share** shows a different
   banner and drops you back at the form, the score is never handed to the
   partner in that case.

If you want to prove it's real and not faked, open the browser's Network tab
before clicking Start Verification. You'll see the actual `POST
http://localhost:8787/api/scores` request fire against the real backend, and
the score actually sitting in Mongo afterwards.

## Running the automated tests

```bash
npm run test        # runs once
npm run typecheck    # TypeScript check, no emit
npm run build        # production build
npm run size         # checks the built bundle against the 10 KB budget
```

All four should pass clean before a demo. If `npm run test` shows a weird old
result (fewer tests than expected), close it and run it again, this repo
lives inside a OneDrive-synced folder and the sync occasionally serves a
slightly stale file for a moment.

## What's fake right now (so nobody's surprised)

- The bank connection screen is a fake page with two buttons, not real
  Yodlee FastLink - see `backend/src/routes/fastlink.routes.ts`.
- Everything only runs on `localhost`, there's no public URL yet.
- There's no hosted-fallback path (only the inline embedded widget exists)
  and no accessibility audit has been done yet.
- The score itself is `Math.random()` in `backend/src/routes/scores.routes.ts`,
  not the real scoring engine.

Auth and the database are real now - the backend runs against Mongo, keys are
hashed, and every score is gated by a per-flow session token, not a shared
hardcoded string.

## Troubleshooting

- **Port already in use**: something's already running on 8787 or 5500.
  Close whatever terminal has it, or kill the process.
- **Demo page loads but the widget never appears**: check you ran
  `npm run build` after the last code change, and that `npm run dev` inside
  `backend/` is actually still running in its terminal.
- **Bank connection screen is blank**: the iframe loads from the backend on
  8787, make sure it's running and that `MONGODB_URI` is actually reachable.
- **"Invalid partner API key"**: run `npm run seed:partner` in `backend/` and
  make sure the key it printed matches `OCCUBUY_PARTNER_API_KEY` in
  `demo/mockPartnerWebApp.html`.
